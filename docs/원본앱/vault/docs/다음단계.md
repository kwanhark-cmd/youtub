# 다음 단계 설계 (이번 버전에서는 구현하지 않음)

## 1. 자동 채우기

### 1-1. 안드로이드 자동완성(Autofill Service)
- 네이티브 `AutofillService`(Kotlin)를 추가하고, 금고는 Flutter 쪽에 있으므로 **잠금 해제가 필요한 응답**(`FillResponse.setAuthentication`)을 돌려준다.
- 흐름: 다른 앱 로그인 칸 → 시스템이 서비스 호출 → "구독·계정 비서로 채우기" 표시 → 누르면 우리 앱의 잠금 해제 화면(생체/마스터 비밀번호) → 사용자가 계정 고름 → 그 한 건만 `Dataset` 으로 반환.
- 앱 식별: 패키지 이름 + 서명 인증서 해시, 웹은 `webDomain`. 계정에 `androidPackages`, `domains` 필드 추가(데이터 버전 3, `migrations.dart` 에 변환 추가).
- 잠긴 상태에서는 어떤 이름·아이디도 미리 보여 주지 않는다("잠금 해제 후 선택"만).

### 1-2. 브라우저 확장(크롬·엣지)
- 확장 ↔ 데스크톱 앱: **Native Messaging**(표준 입출력) 사용. 확장은 비밀번호를 저장하지 않는다.
- 요청마다 앱 창에서 사용자 승인(또는 최근 N분 이내 승인) 후 해당 도메인 계정 1건만 전달.
- 피싱 방지: 저장된 도메인과 정확히 일치할 때만 제안, 하위 도메인은 사용자 확인.

## 2. "1번 앱" 등 다른 앱과 연결 — 사용자 승인 후에만 비밀번호 전달

### 인터페이스(안)
```
요청: { requestId, callerAppId, callerSignature, service: "facebook", purpose: "로그인 자동화", fields: ["loginId","password"] }
응답: { requestId, approved: true/false, data?: { loginId, password }, expiresAt }
```
- 전달 경로: 안드로이드 `Intent` + 결과 반환(`startActivityForResult` 계열), 데스크톱은 로컬 소켓/Named Pipe(127.0.0.1 전용, 매 연결 무작위 토큰).
- **매번 승인 화면**: "OO 앱이 페이스북 비밀번호를 요청합니다 — 허용/거절", 생체 인증 또는 마스터 비밀번호 필요.
- 허용 목록: 처음 승인할 때 호출 앱의 서명 해시를 등록, 다음부터는 서명이 다르면 거절.
- 기록: "언제 어느 앱에 어떤 서비스 정보를 줬는지"만 금고 안에 기록(값은 기록 안 함).
- 잠긴 상태·자동 잠금 직후에는 무조건 거절. 음성으로는 절대 전달하지 않음.

### 코드 위치(예정)
- `lib/logic/share_request.dart`: 요청 검증, 허용 목록, 기록
- `lib/ui/screens/share_approval_screen.dart`: 승인 화면
- 플랫폼 연결: `android/.../ShareRequestActivity.kt`, 데스크톱 `lib/app/local_bridge.dart`

## 3. 그 밖에
- 외부 음성 서비스(설정에 자리만 있음): `SpeechPort`/`TtsPort` 를 구현하는 새 클래스 추가로 교체 가능. 비밀번호 차단은 `VoiceAssistant` 에서 하므로 그대로 유지됨.
- 다른 AI 제공자: `MailAiProvider` 를 구현하는 클래스를 추가하고 설정 화면에 선택지 추가.
- 기기 간 동기화: 금고 파일은 이미 암호화되어 있으므로, 서버에는 암호문만 올리는 방식(서버도 못 보는 구조)으로 설계 가능.
- 아이폰: 플랫폼 폴더 추가 + 권한 문구만 필요(코드는 공통).
