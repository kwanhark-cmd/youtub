# 판매·배포 전 준비 (반드시 읽기)

이 앱은 비밀번호를 다루므로, **판매·공개 배포 전에 외부 전문 업체의 보안 점검(침투 테스트·코드 감사)을 꼭 받아야 합니다.**
지금 버전은 자체 테스트를 통과한 **시험용**입니다.

## 1. 외부 보안 점검에서 꼭 봐야 할 것
| 영역 | 확인할 내용 | 지금 상태 |
|---|---|---|
| 암호화 | AES-256-GCM·Argon2id 사용법, 난수(nonce) 재사용 없음, AAD 사용, 키 수명 | `cryptography` 2.9.0 사용, nonce 매번 무작위 12바이트 |
| 키 생성 강도 | Argon2id m=19MiB, t=2 가 충분한지(기기 성능 따라 상향) | 머리글에 설정 저장 → 올리기 쉬움 |
| 메모리 | 잠근 뒤 키·비밀번호가 메모리에 얼마나 남는가(Dart 는 즉시 지우기 어려움) | 참조 제거만 함 → 점검 필요 |
| 생체 인증 | 지금은 "OS 보안 저장소의 기기 키 + local_auth 확인" 방식. **Keystore 키를 생체 인증에 묶는 방식**(`AndroidOptions.biometric`, iOS/macOS `accessControl`)으로 강화 권장 | 개선 필요 |
| 실패 지연 | 실패 횟수가 머리글 파일에 있어 파일을 직접 고치면 초기화 가능(오프라인 공격은 Argon2 가 방어) | 알려진 한계 |
| 클립보드 | 다른 앱·클립보드 기록 앱이 30초 안에 읽을 수 있음. 안드로이드 13+ 는 "민감한 내용" 표시(ClipDescription.EXTRA_IS_SENSITIVE) 추가 권장 | 개선 권장 |
| 화면 캡처 | 안드로이드 FLAG_SECURE 적용. 윈도우(SetWindowDisplayAffinity)·맥은 미적용 | 개선 권장 |
| 지메일 연결 | OAuth PKCE + 127.0.0.1 임시 주소. 구글 "민감한 범위(gmail.readonly)" 앱 검수 필요(일반 배포 시 필수) | 검수 필요 |
| AI 전송 | 카드번호 가림·필요 부분만 전송. 이메일 주소·이름은 전송될 수 있음 → 개인정보처리방침에 명시 | 문서화 필요 |
| 로그 | 비밀처럼 보이는 값 가림 + 계정 정보 미기록 테스트 | 점검 권장 |
| 의존성 | 패키지 버전 고정(`pubspec.yaml`), 취약점 검사(예: OSV) 정기 실행 | 정기 실행 필요 |

## 2. 앱 서명·스토어
- **안드로이드**: 지금 APK 는 디버그 키 서명. 업로드 키 만들기 → `android/key.properties`(저장소에 넣지 말 것, `.gitignore` 처리됨) → Play 앱 서명. 패키지 이름 `com.kwanhark.vaultassistant.account_vault` 확정.
- **윈도우**: 코드 서명 인증서(EV 권장) 또는 MSIX + Microsoft Store.
- **맥**: Apple Developer ID 서명 + 공증(notarization). 이때 키체인 접근 그룹(keychain-access-groups) 권한을 다시 넣어 생체 인증 키 보관을 강화.
- **아이폰**: `flutter create --platforms ios .` 후 Face ID 설명(NSFaceIDUsageDescription)·마이크 권한 문구 추가, 앱 심사.
