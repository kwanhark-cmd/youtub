# 수정 보고 — 버전 1.1.0 (업데이트 방식 · 오류 대비 · 화면 재설계)

## 가장 중요한 것: 금고는 그대로 열립니다
- 금고 파일 형식, 키 생성 방식(Argon2id m=19MiB·t=2·p=1), 파일 이름·위치는 **하나도 바꾸지 않았습니다.**
- 1.0.0 으로 만든 "기준 금고"(가짜 자료, 알려진 비밀번호)를 `test/fixtures/vault_v1.0.0` 에 고정하고,
  새 버전이 **같은 마스터 비밀번호로 열어 모든 항목이 똑같은지** 자동 테스트합니다(`test/compat`).
  복구 코드·백업 파일·"새 버전이 저장해도 옛 형식 유지"·"금고가 있으면 첫 실행 마법사 건너뜀"까지 확인.
- 이 테스트는 GitHub Actions 에서 **가장 먼저** 돌고, 실패하면 빌드가 멈춥니다.
- 앱 식별자(안드로이드 패키지, 맥 번들 ID, 윈도우 회사·제품 이름·설치 AppId)와 자료 위치도 테스트로 고정했습니다.

## 바뀐 것
### 1. 업데이트 방식
- **설정 맨 위 "업데이트 확인"**: GitHub Releases 최신 버전 확인 → 사용자가 누르면 **금고 자동 암호화 백업** → 내려받기 → **해시(SHA-256) 확인**(Releases 본문과 SHA256SUMS.txt 두 곳 모두와 일치해야) → 설치 시작. 자동으로 내려받지 않습니다.
  - 안드로이드: APK 설치 화면 / 윈도우: 설치 프로그램 실행 / 맥·리눅스: 내려받은 폴더를 열어 안내(맥 보안 상자 때문에 앱이 스스로 바꾸지 못함)
- **배포 자동화**: 버전 태그(`v1.1.0`)를 올리면 GitHub Actions 가 4개 플랫폼 파일 + `SHA256SUMS.txt` + 한국어 변경 내역(`CHANGELOG.md`)을 Releases 에 올립니다.
- 윈도우는 이제 **설치 파일**(`…-windows-setup.exe`)로 배포. 덮어쓰기 설치, 금고는 `%APPDATA%` 에 그대로.
- 안드로이드 서명 키를 GitHub Secrets 에서 읽도록 연결(키 등록은 사용자가 한 번: `docs/안드로이드서명키.md`).
- 사용자 목록 파일이 지워지거나 망가져도 금고 폴더를 다시 찾아 열 수 있게 함.

### 2. 사용 중 오류 대비
- **보던 화면·위치 유지**: 목록을 내려 보다가 자동 잠금·저장·설정 변경이 있어도 맨 위로 튀지 않고, 잠긴 뒤 다시 열면 **보던 화면과 위치로 돌아옵니다**(메모리에만 기억, 비밀 정보 없음).
- **"다시 시도" 때 앱이 죽던 문제 차단**: 모든 대화상자를 앱 전체 길잡이(navigatorKey)로 띄우고, 화면이 사라졌는지 확인. 실패 창에는 "다시 시도"·"문제 신고"(금고가 열렸을 때만)·"다음 행동" 버튼.
- **모든 실패를 단계와 함께 기록**(잠금 해제·생체 인증·백업·복원·지메일·AI·업데이트·유출 확인·파일). 비밀번호·계정·카드 정보는 가림.
- 금고 파일이 손상되면 **잠금 화면에서 바로 백업 파일로 복원** 가능.
- **연결 상태를 따로 표시**: "지메일 / AI / 생체 인증" 각각을 홈 아래쪽과 설정에 표시, 저장 즉시 반영.
- **파일 불러오기 버튼**: AI 열쇠 파일, 구글 JSON, 비밀번호 CSV, 백업 파일.
- **빈 화면 안내**: 구독·계정·크레딧이 0개일 때 다음 행동 버튼(첫 구독 넣기, CSV 불러오기 등). 생체 인증 불가 기기 안내.
- **앱 꾸미기**: 표시 이름, 색 테마 4가지, **위장 이름·아이콘(계산기·메모)** — 안드로이드는 홈 화면 아이콘까지, 윈도우·맥은 앱 제목 + 바로가기 아이콘 바꾸는 법 안내.

### 3. 화면 재설계
- 홈: **이번 달 구독료 큰 숫자**(주요색 카드) → **오늘 할 일**(노랑·빨강으로 채운 카드) → 이번 주 결제 예정 → 2열 타일(구독/계정/금고 건강/만료 알림) → 그 밖의 메뉴 → 연결 상태 띠(가장 작게).
- 테두리만 있던 상자 → **배경을 채운 카드 + 부드러운 그림자**(어두운 모드도 바탕보다 밝은 카드).
- 구독 카드: **서비스 색 띠 + 서비스 색 아이콘** + 이름 + 요금 + 다음 결제일. 만료 임박은 테두리 색으로 맨 위.
- 계정 목록: 서비스 아이콘 + 아이디 + 복사 버튼(비밀번호는 목록에 없음). 금고 건강: **점수 원형** + 항목별 배지.
- 잠금 화면: **큰 3D 자물쇠**, 큰 입력칸·보기 버튼, 크고 색 있는 생체 인증 버튼(애니메이션 0.5초, 열리는 속도와 무관).
- 설정: 묶음 카드(금고·잠금 / 지메일 / AI / 보기 / 앱 꾸미기 / 백업·복원 / 도움), **위험(초기화)은 맨 아래 빨강 카드**.
- 글자 위계 4단계(큰 숫자 44 > 화면 제목 28 > 카드 제목 22 > 본문 18), 카드 간격 1.5배.

### 4. 이 앱 전용
- **지메일 연결 도우미**(설정 → 지메일): 콘솔 바로가기 → Gmail API 사용 → 동의 화면·테스트 사용자 → "데스크톱 앱" 클라이언트 → JSON 불러오기 → 연결("고급 → 이동" 안내) → 7일마다 끊김 안내.
- 크레딧 **"내일 다시 알림"** 버튼(만료 14일 후 알림 중단은 유지).
- 생체 인증 실패(플러그인 오류·보안 저장소 오류·키 없음)는 모두 마스터 비밀번호로 전환됨을 테스트로 확인. 윈도우 우회 설정이 빠지면 CI 가 실패하도록 검사 추가.
- 자동 채우기·1번 앱 연동은 이번에도 설계만(복사 버튼 유지).

## 업데이트 방법 (사용자용)
1. **복구 코드가 종이에 적혀 있는지 먼저 확인하세요.**
2. 앱 → 설정 → 맨 위 **"업데이트 확인"** → "새 버전 확인하기" → "백업하고 내려받아 설치".
   (또는 GitHub → Releases → 최신 버전에서 기기에 맞는 파일)
3. 설치 = 덮어쓰기. 금고는 그대로이고 **같은 마스터 비밀번호로 열립니다.** 앱을 "삭제"하지는 마세요.
4. 안드로이드는 서명 키를 한 번 등록해야 이후 업데이트가 됩니다: `docs/안드로이드서명키.md`.
   **1.0.0 을 안드로이드에 설치해 쓰고 있었다면**: 1.0.0 은 시험용 키로 서명되어 있어 1.1.0 을 "업데이트"로 설치할 수 없을 수 있습니다.
   그때는 1.0.0 앱에서 **설정 → 백업 파일 만들기 → PC 로 옮기기** → 앱 삭제 → 1.1.0 설치 → 백업 복원 순서로 하세요.
   윈도우·맥·리눅스는 덮어쓰기로 그대로 열립니다(1.0.0 은 윈도우 설치 파일이 아니었으므로, 설치 파일로 설치한 뒤 같은 마스터 비밀번호로 열면 됩니다 — 자료는 `%APPDATA%` 에 그대로).

## 검증
- 금고 호환 테스트 14개(기준 금고·식별자·자료 위치) 통과 — **최우선**
- 전체 자동 테스트 통과(기존 95개 포함 → 130개 이상), 린트·형식 통과, 이 환경 리눅스 빌드 성공
- 새 테스트: 업데이트(해시 일치/불일치·해시 없음·버전 비교·화면 흐름), 스크롤·화면 복귀, 실패→다시 시도, 사라진 화면 대화상자, 문제 신고 비밀 없음, 생체 인증 전환, 파일 불러오기, 다시 알림, 디자인(중요도 순서·색 테마 대비·상태 즉시 반영·큰 글씨·작은 화면·어두운·고대비)
- GitHub Actions 전 플랫폼 통과(안드로이드·윈도우 설치 파일·맥·리눅스), **Releases v1.1.0 게시 확인**(파일 4개 + SHA256SUMS.txt + 한국어 변경 내역), 앱의 업데이트 확인 코드가 실제 Releases 를 읽고 4개 파일 해시를 모두 찾음(`tool/check_live_release.dart`)
- 보안 체크리스트: `docs/검증/수정검증.md`, 누락 점검: `docs/검증/누락점검.md`

## 못 한 것과 이유
| 항목 | 이유 |
|---|---|
| 안드로이드 출시 서명 키를 GitHub Secrets 에 등록 | 저장소 관리자만 가능(이 작업 권한으로는 불가). 순서 안내 문서 작성 |
| 맥 "새 앱으로 자동 교체" | 맥 보안 상자(샌드박스)가 앱이 자기 자신을 바꾸는 것을 막음 → 해시 확인 후 내려받은 폴더를 열어 안내 |
| 윈도우·맥 바탕 화면 아이콘 자동 변경 | 운영체제가 앱에 허락하지 않음 → 앱 제목 변경 + 바꾸는 법 안내 |
| 실제 기기에서 생체 인증·업데이트 설치 화면 확인 | 이 환경에 장치 없음 → 코드·테스트로 확인, 실기기 확인은 사용자 몫 |
| 자동 채우기, 1번 앱 연동 | 지시서대로 설계만 유지(`docs/다음단계.md`) |
