# 안드로이드 서명 키 고정하기 (한 번만, 꼭 필요)

## 왜 필요한가요?
안드로이드는 **같은 서명 키**로 만든 새 버전만 "업데이트"로 받아들입니다.
키가 매번 바뀌면 새 버전을 설치할 때 "앱이 설치되지 않았습니다"가 나오고,
기존 앱을 지워야 하는데 **앱을 지우면 금고도 함께 지워집니다.**
그래서 키를 한 번 만들어 GitHub 의 비밀 보관함(Secrets)에 넣어 두면, 이후 모든 버전이 같은 키로 서명됩니다.

> 키가 아직 등록되지 않았다면 Releases 변경 내역에 "안드로이드 서명: 시험용 키"라고 나옵니다.
> 그 상태에서 안드로이드 앱을 바꿔 설치해야 하면: **먼저 설정 → 백업 → 백업 파일 만들기**로 백업을 받아 PC 에 옮긴 뒤 진행하세요.

## 순서 (PC 에서 10분)
1. 자바가 설치된 PC 에서(안드로이드 스튜디오가 있으면 이미 있음) 명령창을 엽니다.
2. 아래 한 줄을 붙여 넣고 실행합니다. 비밀번호를 두 번 묻습니다(**긴 비밀번호, 종이에 적어 두기**).
   ```
   keytool -genkeypair -v -keystore release.jks -alias vault -keyalg RSA -keysize 4096 -validity 36500 -dname "CN=account vault"
   ```
3. 만든 `release.jks` 를 글자로 바꿉니다.
   - 윈도우(PowerShell): `[Convert]::ToBase64String([IO.File]::ReadAllBytes("release.jks")) | Set-Clipboard`
   - 맥: `base64 -i release.jks | pbcopy`
4. GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret** 에서 4개를 만듭니다.

| 이름 | 값 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | 3번에서 복사한 긴 글자 |
| `ANDROID_KEYSTORE_PASSWORD` | 2번에서 정한 비밀번호 |
| `ANDROID_KEY_ALIAS` | `vault` |
| `ANDROID_KEY_PASSWORD` | 2번에서 정한 비밀번호(같은 것) |

5. `release.jks` 파일과 비밀번호를 **USB 등 안전한 곳에 따로 보관**하세요. 잃어버리면 다시는 같은 키로 업데이트할 수 없습니다.
   이 파일을 저장소·메일·메신저에 올리지 마세요(저장소는 공개되어 있습니다).

## 확인
다음 버전부터 Releases 변경 내역에 "안드로이드 서명: 출시용 키"가 나오면 성공입니다.
처음 출시용 키로 바뀌는 그 한 번은, 시험용 키로 설치한 앱과 키가 다르므로 **백업 → 앱 삭제 → 새로 설치 → 백업 복원** 순서가 필요합니다.
